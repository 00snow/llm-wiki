# 檢索增強生成（Retrieval-Augmented Generation, RAG）

> 先從外部資料中「檢索」相關內容，放進 prompt，再讓 LLM「生成」答案的方法。

## 重點
- 解決 LLM **知識有截止日**、**不知道私人資料**的問題。
- 流程：切塊 → 轉 embedding → 存入向量資料庫 → 依問題檢索 → 生成。
- 答案可以**附上來源**，方便查證。
- 資料更新只要重建索引，不必重新訓練模型。
- 弱點：檢索不到或找錯段落，答案就會跟著錯。

## 說明

```
文件 ──切塊──▶ 片段 ──embedding──▶ 向量資料庫
                                     │
使用者問題 ──embedding──▶ 找最相近的 k 個片段
                                     │
            問題 + 片段 ──▶ LLM ──▶ 答案（附來源）
```

embedding 的概念和 [[tokenization]] 中把 token 轉成向量類似，
只是這裡是把一整段文字轉成一個向量，意思相近的段落向量也會相近。

### RAG vs. LLM Wiki
RAG 每次提問都重新檢索、重新拼湊，知識不會累積；
[[llm-wiki]] 則是讓 LLM 事先把資料整理成 wiki，之後查詢時讀的是整理好的頁面。

## 例子
公司客服機器人：把產品手冊做成向量資料庫。使用者問「保固多久？」，
系統找出手冊中講保固的段落，連同問題交給 LLM，回答「兩年，詳見手冊第 5 章」。
