# 幻覺（Hallucination）

> LLM 自信地說出不正確、或根本不存在的內容。

## 重點
- 原因：LLM 是在預測「看起來合理」的下一個 token，不是在查證事實。
- 常見情況：捏造引用文獻、記錯數字、編出不存在的人名或 API。
- 語氣越肯定不代表越正確。
- 降低方法：[[rag]] 提供依據、[[prompt-engineering]] 允許回答「不知道」、要求附來源。
- 重要資訊一定要**人工查證**。

## 說明
回想 [[large-language-model]] 的運作方式：模型每一步都挑一個機率高的 token。
如果訓練資料裡沒有答案，模型仍然會挑出「語法上很通順」的字，
結果就是一段流暢但錯誤的文字。temperature 設得越高，越可能出現天馬行空的內容。

| 方法 | 為什麼有效 |
|------|-----------|
| RAG 提供參考資料 | 讓模型有依據可以照著說 |
| 允許回答「不知道」 | 給模型一條不用硬掰的出路 |
| 要求附上來源 | 方便人工查證 |
| 降低 temperature | 減少隨機性 |

## 例子
問模型「請列出三篇討論某冷門主題的論文」，它可能給出格式完美、作者看似合理，
但實際上**不存在**的論文標題。

## 相關概念
- [[large-language-model]]：幻覺來自 LLM 的生成方式
- [[rag]]：用外部資料降低幻覺
- [[prompt-engineering]]：用 prompt 設計降低幻覺
