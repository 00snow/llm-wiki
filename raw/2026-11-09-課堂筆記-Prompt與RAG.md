# 課堂筆記 2026-11-09：怎麼把 LLM 用好

## Prompt
- 寫清楚：角色、任務、限制、輸出格式
- few-shot：先給幾個範例，模型會模仿格式
- 叫它「一步一步想」（chain of thought）在推理題常常比較準
- 給它「不知道就說不知道」的出口，可以減少亂掰

## RAG（Retrieval-Augmented Generation）
- 問題：模型的知識停在訓練時間，也不知道我們自己的資料
- 作法：先「檢索」相關文件 → 塞進 prompt → 再讓模型「生成」答案
- 流程：文件切塊 → 轉 embedding 存向量資料庫 → 問題也轉 embedding → 找最相近的幾塊
- 優點：可以引用來源、資料更新不用重新訓練、比較少幻覺
- 缺點：檢索不到 / 找錯就會答錯；切塊大小要調

## LLM Wiki（老師最後提的）
- RAG 每次問都重新找、重新拼湊，知識不會「累積」
- LLM Wiki 的想法：讓 LLM 把讀過的資料**整理成一份 wiki**，持續更新、互相連結
- 三層：raw 原始資料（人放）→ wiki（LLM 寫）→ schema 規則檔（像 CLAUDE.md，告訴 LLM 怎麼維護）
- 三個動作：ingest（收資料）、query（問問題）、lint（定期檢查矛盾、壞連結）
- 人負責找資料和問好問題，LLM 負責無聊的整理和交叉引用
- 作業：自己做一個！
