# 用 LLM Wiki 做教學簡報：流程和反思

簡報在 [`index.html`](index.html)，知識庫在 [`wiki/`](../wiki/index.md)，每一輪檢查的紀錄在 [`build/check_report.md`](build/check_report.md)。

## 一、LLM Wiki

主題是深度學習入門，想做給完全沒碰過 AI 的人看，從「AI 是什麼」一路講到 CNN。

一開始沒有直接叫 AI 生內容，而是先跟它討論要收哪些東西（NN、CNN、卷積、loss function、optimization）、讀者是誰、每一頁要怎麼寫。最後定成「先用生活比喻，再講原理，最後給一題可以動手算的例子」，這些規則寫在 `AGENTS.md`，之後 AI 收資料、寫頁面都照這份規則走。

資料一共收了 8 份，放在 `raw/`：維基百科的人工智慧和卷積、Google 機器學習速成課程的神經網路／損失／梯度下降、Stanford CS231n 的反向傳播和 CNN，還有 Karpathy 講 LLM Wiki 的那篇。每收一份都會在 `wiki/log.md` 記一筆。

## 二、教學簡報

簡報有 25 張教學頁，最後再加 3 張講這份簡報是怎麼做出來的。每張底下有來源標籤，點了會跳回它參考的那一頁 Wiki，所以簡報裡講的東西都查得到出處。

操作：左右鍵換頁，N 看講者備註，T 切深淺色。用手機開會變成往下滑的卡片。

## 三、流程設計

![流程圖](graph.svg)

整個流程分六步：

- A 取得資料：我挑來源，AI 幫忙剪成 `raw/` 裡的檔案，再整理成 Wiki 頁面。
- B 查詢 Wiki：`query_wiki.py` 把 Wiki 整理成一份資料包，給下一步的 AI 看。裡面有各頁重點、每頁出現過的數字、術語表，還有標成「待查證」的內容。
- C 整理重點：AI 讀資料包，寫出每張投影片的大綱（`outline.json`）。
- D 內容檢查：`check_outline.py` 檢查大綱，有錯就列出來，並寫明要退回哪一步。
- E 產生簡報：`build_slides.py` 把大綱和 Wiki 的圖組成 `index.html`。
- F 版面檢查：在瀏覽器裡用電腦和手機尺寸各看一次，逐張截圖。

整條流程只有 C 是 AI 在寫，其他都是程式。原因很簡單：AI 擅長把東西講得好懂，但數中文字數、算數學、記住哪個術語教過沒，它常常出錯。這些交給程式檢查，結果每次都一樣，也可以重跑。

D 檢查的項目：

| 檢查 | 內容 | 錯了退回 |
|---|---|---|
| SOURCE | 每張都要標來源 | C |
| NUMBER | 簡報裡的數字要能在引用的 Wiki 頁找到 | C，Wiki 本身沒有就回 A |
| UNVERIFIED | 不能用 Wiki 裡標「待查證」的內容 | A |
| MATH | 把算式實際算一次，看等號兩邊對不對 | C |
| JARGON | 術語要先解釋過才能用 | C |
| LENGTH | 每張的字數和條數有上限，太擠初學者看不下去 | C |
| DIAGRAM / QUIZ | 圖檔要存在，測驗答案要在選項裡 | C |
| MISMATCH | 圖和算式要是同一個例子（第二版才加） | C |

會重複的地方：

- C 和 D 之間來回最多。D 每次整份重新檢查，但 C 只重寫有錯的那幾張，已經過關的不動，免得被 AI 改壞。最多跑 3 輪，還不過就停下來由我處理。
- 每次產生簡報後都要做 F。F 抓到的如果是樣式問題（字太小、排版怪），就改模板重跑 E；如果是內容問題，就要回 C 改大綱，再過一次 D。
- A 和 B 只在缺資料時才會重跑。

我覺得最重要的一點是，每種錯誤都要能說出該退回哪一步。不然只知道「有錯」，不知道是要改一張投影片，還是要回去補資料。

## 四、實際跑一次之後的反思

實際跑的過程：

| 輪 | 結果 |
|---|---|
| 1 | 第一版 24 張，檢查出 16 個錯，其中 13 個其實是檢查程式誤判。封面和目錄只是列出接下來要講什麼，不該算是「用了還沒教的術語」（11 個）；目錄頁的連結代碼被算進字數，條數上限也沒有另外設（2 個） |
| 2 | 修好檢查程式後剩 5 個真的錯：3 張字太多，2 張先用了後面才教的術語 |
| 3 | 只重寫那 5 處，0 錯 |
| F | 截圖看到 3 個 D 抓不到的問題：網址改頁碼不會換頁、圖太小、還有一張把最大池化的圖配上卷積的算式 |
| 4 | 池化那張退回 C，拆成兩張，0 錯 |
| 5 | 把規則先寫進資料包後，新寫的 3 張一次就過 |
| 6 | 截圖發現流程圖太小，改成寬版，0 錯 |

### 哪個節點最常出錯？

C，也就是 AI 寫大綱那一步。真正的內容錯誤都出在這裡，主要是三種：中文字數常常超過、寫的時候會順口提到後面才教的術語、把兩個不同的例子放在同一頁。

另外沒想到的是，第二常出錯的是檢查程式本身。第一輪 16 個錯有 13 個是誤判，如果沒有回頭去看，可能會為了過檢查去改本來沒問題的投影片。

### 怎麼調整檢查流程？

第一個改法是把規則往前放到 B。本來字數上限和術語規則只寫在檢查程式裡，C 寫的時候根本看不到，只能寫完被退回再改。後來把這些限制直接放進資料包最上面，C 一開始就知道要遵守什麼。之後新寫的投影片一次就過了。

第二個改法是把一個原本只能靠 F 截圖發現的問題，移到 D 自動檢查。池化那張的數字和算式都是對的，所以 D 原本完全沒發現，是看截圖才知道圖和算式在講不同的東西。後來加了 MISMATCH：找出那張圖在 Wiki 裡屬於哪一段，算式裡的數字至少八成要出現在那一段。拿舊的錯誤版本測試，只對到 29%，會被擋下；其他動手算的投影片都是 100%。

一開始我是拿圖片裡的數字來比，結果舊版池化那張還是有 86% 對得上，因為池化圖裡都是 0 到 9 的小數字，太容易撞到。所以才改成跟 Wiki 的段落比。

### 流程圖有沒有改？

有改三個地方：

1. B 多接了一個 `rules.json`，就是上面說的把規則先告訴 C。事先講清楚比事後退回省事，每退回一次就要多跑一輪。
2. D 多了 MISMATCH 檢查。能用程式檢查的，就不要留到最後靠眼睛看。
3. F 的退回分成兩條。一開始 F 只會退回 E，但池化那張的問題改模板沒用，一定要回 C 改大綱，所以多拉了一條回 C 的線。

### 這次做法的限制

這次寫大綱的 AI 和幫我寫檢查程式的 AI 是同一個，它本來就知道會檢查什麼，所以「第五輪一次就過」不太能證明規則前移真的有效。比較公平的做法是換一個只看得到資料包、不知道檢查規則的 AI 來寫大綱，再看它會不會一次通過。
